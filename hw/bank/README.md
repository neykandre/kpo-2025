# Учет финансов - ВШЭ Банк

## Общая идея решения
Консольное приложение для управления личными финансами с поддержкой:
- CRUD операций для счетов, категорий и операций
- Аналитики финансов (баланс за период, группировка по категориям)
- Работы с встроенной H2 базой данных
- Модульной архитектуры с использованием паттернов проектирования

Основные сущности:
- `BankAccount` - банковский счет
- `Category` - категория операций
- `Operation` - финансовая операция

## Принципы SOLID и GRASP

### SOLID
1. **Single Responsibility**  
   Каждый класс имеет строго определенную зону ответственности

2. **Open/Closed**  
   Система расширяется через новые реализации интерфейсов

3. **Liskov Substitution**  
   Наследники полностью совместимы с базовыми типами

4. **Interface Segregation**  
   Узкоспециализированные контракты для компонентов

5. **Dependency Inversion**  
   Зависимости внедряются через абстракции

### GRASP
1. **High Cohesion**  
   Логическая целостность компонентов

2. **Low Coupling**  
   Минимальные зависимости между модулями

## Реализованные паттерны GoF

### Порождающие
1. **Фабрика (Factory)**  
   Централизованное создание объектов через `*Factory` классы

2. **Команда (Command)**  
   Иерархия классов-команд (`CreateBankAccountCommand` и др.)

3. **Компоновщик (Composite)**  
   Объединение команд в сложные операции через `CompositeCommand`

### Структурные
1. **Фасад (Facade)**  
   Упрощение работы с подсистемой через `*Facade` классы

2. **Прокси (Proxy)**  
   Кэширующий слой `FinanceRepository` для работы с БД

### Поведенческие
1. **Шаблонный метод (Template Method)**  
   Общая логика импорта в `DataImporter`

## Использование технологий
- **Spring Framework** для DI и управления зависимостями
- **H2 Database** - встроенная реляционная БД
- **JPA/Hibernate** для ORM-маппинга
